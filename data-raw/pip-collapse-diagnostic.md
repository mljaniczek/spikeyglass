# Why SSJGL's PIPs collapse in the DiNA simulation

Script: `data-raw/pip-collapse-diagnostic.R`. Results:
`data-raw/pip-collapse-diagnostic-summary.csv` (one row per cell and ladder
step) and `data-raw/pip-collapse-diagnostic-oracle.csv`. Figures:
`pip-collapse-trace.png` and `pip-collapse-threshold.png`. The per-iteration
trace (`pip-collapse-diagnostic-trace.csv`, about 2 MB) and the per-cell cache
are regenerated by the script and not committed.

## Question

In the DiNA simulation (`03_estimate.R::run_ssjgl`), SSJGL returned
`problist1` (P(delta = 1), edge inclusion) and `problist2` (P(xi = 1),
cross-group difference) that were essentially 0 at p = 250. Those fits used:

- a scale-free gold standard, n from 250 to 5000 per group, K = 2;
- `lambda0 = lambda1 = lambda2 = 1`, `a = b = 1`, `doubly = TRUE`,
  `normalize = FALSE` (raw data);
- `v0s = lambda1 / (lambda1 + 5 * (1:3))`, i.e. lambda1/v0 = 6, 11, 16;
- penalty `"fused"` (SSJGL) or `"group"` (SSJGL_GGL).

A different run (p = 200, lambda1 = 0.5, v0 down to 0.01, so lambda1/v0 = 50,
b = p) over-selected instead. What drives the collapse?

## The E-step, written out

`gete.doubly()` weighs three cells per pair (j, k). With
A = sum_g |theta_g,jk|, D = |theta_1,jk - theta_2,jk| (fused, c = 1 for
G = 2) or sqrt(sum_g theta_g,jk^2) (group, c = 1), and r = lambda/v0 with
v1 = lambda = 1:

    log[(1,0) / (0,0)] = -G log r + logit(pi_delta) + (r - 1) A
    log[(1,1) / (1,0)] = -c log r + logit(pi_xi)    + (r - 1) D

So each log-odds has a data-free normalising term (-G log r), a log-pi term
and a |theta| term with slope r - 1. Ignoring the (1,1) cell, the PIP is a
logistic function of A that crosses 1/2 at

    A* = (G log r - logit(pi_delta)) / (r - 1).

The E-step never sees the data or n: given theta-hat and pi, the PIP is a
fixed function of |theta-hat|. The pi update
pi = (a + sum_{j<k} PIP_jk - 1) / (a + b + N - 2), with N = p(p-1)/2 pairs,
is close to the mean PIP.

## Design

An instrumented copy of the R EM loop of `ssjgl()` (impute = FALSE, with the
same warm start between ladder steps) records pi_delta, pi_xi, the PIP
quantiles, the fraction of PIPs > 0.5 and < 1e-6, the log-odds components,
A*, and the |theta| scale at every EM iteration. It matches `ssjgl()` (C++
path) to 5e-14 in theta, PIPs and pi on two small cases (fused/standardised
and group/raw, p = 50).

Grid: fused penalty, doubly = TRUE, lambda0 = lambda1 = lambda2 = 1, a = 1,
K = 2, n = 250 per group, one replicate per cell:

| factor | levels |
|---|---|
| data | `sim`: `simulate_ssjgl_data(graph_type = "scale-free", perturb_prob = 0.2/p)`; `dina`: DiNA's own gold standards (SF-p50n1000, SF-p100n1000, SF-p250n250, rep_0001), sampled as DiNA's `gen_dat()` does |
| p | 50, 125, 250 (sim); 50, 100, 250 (dina; DiNA has no p = 125) |
| scale | raw (as in DiNA) vs `standardize = TRUE` |
| b | 1 (DiNA) vs p |
| ladder | DiNA: lambda1/v0 = 6, 11, 16; default `make_v0_ladder(1)`: 10, 31.6, 100 |

Plus the group penalty at p = 250 (raw, b = 1, both ladders and both data
sources). Six follow-up cells on the DiNA setting (DiNA data, p = 250, raw,
b = 1, fused), each run with both ladders:

- a second replicate (gold standard rep_0002, new data);
- n = 2000 per group;
- pi_delta and pi_xi held fixed at the true densities (no pi feedback).

There are 58 cells in all.

On the data scale: DiNA's precision matrices have a unit diagonal and
off-diagonal entries with median |theta| = 0.18 (p = 250). The raw variances
are therefore about 1.25 (median sd 1.12), so the raw-data theta is about 20%
smaller than on the correlation scale. With `simulate_ssjgl_data()` the edges
have |theta| = 0.3 and a diagonal loading (median sd 0.86 at p = 250).
`perturb_prob = 0.2/p` is used because the default 0.05 adds about 1550
random edges to group 2 at p = 250 (six times the scale-free edges), unlike
DiNA.

## Mechanism

1. **The root cause is the spike's width set by the DiNA ladder's endpoint
   (lambda1/v0 = 16), not p.** The break-even |theta| for P(delta = 1) = 1/2
   is A* = (G log r - logit pi)/(r - 1), summed over the G = 2 groups. At
   r = 16 and pi near the true density at p = 250, A* = 0.66, i.e. about 0.33
   per group. DiNA's true edges have median |theta| = 0.18 (A = 0.36). Even the
   true Theta puts only 20% of the true edges in the slab (oracle table). At
   r = 100, A* = 0.14 and 95% are in the slab. The spike Laplace(rate 16) and
   the slab Laplace(rate 1) cross at |theta| ~ log(16)/15 = 0.18 per entry,
   which is exactly where DiNA's edge weights sit. The normalising term
   -G log r is p-free, so the "G log(lambda/v0) dominates as p grows"
   hypothesis is rejected. It grows with r, but more slowly than the |theta|
   slope r - 1, so a larger r lowers A*.

2. **The pi update turns "too few slab edges" into a geometric collapse.**
   A pair whose A-hat is below A* gets PIP ~ pi e^{(r-1)A} / r^G, so the
   update multiplies pi by roughly r^-G E[e^{(r-1)A}] per iteration. In the
   DiNA cell (r = 6), pi_delta went 0.19 -> 1.0e-2 -> 4.6e-4 -> 1.9e-5 ->
   8.1e-7, a factor 0.042 per iteration (`pip-collapse-trace.png`, top). A
   lower pi raises A*, which removes more edges from the slab. pi_xi falls
   faster (factor 1e-3 to 1e-7 per iteration) because only 24 of 31,125 pairs
   differ between groups. pi_xi reaches exactly 0.0, which is absorbing:
   log(0) = -Inf in `gete.doubly()` makes every P(xi = 1) exactly 0, and with
   a = 1 the update returns 0 again. This is why `problist2` was identically
   zero. Holding pi at the true density (no feedback) gives 52 instead of 6
   edges with PIP > 0.5 and keeps max PIP2 at 9e-4. So the feedback
   multiplies the collapse about 9-fold, but the threshold is what triggers
   it.

3. **The EM declares convergence while pi is still collapsing.** The
   criterion is max |Delta theta| < 1e-4. Once every off-diagonal weight is
   about 1/v0, theta stops moving and the step ends after 6 to 9 iterations,
   with pi still falling 25-fold per iteration. Steps 1 and 2 of the DiNA
   ladder end at pi_delta ~ 1e-6 to 1e-8, which is not a fixed point. The
   warm start passes theta to the next step, but pi restarts at a/(a + b)
   (0.5 when b = 1), and the collapse repeats at each step
   (`pip-collapse-trace.png`). The default ladder's first step (r = 10)
   collapses in the same way. It recovers only because its later steps
   (r = 31.6, 100) put A* below the edge scale.

4. **It is not specific to p = 250.** With the DiNA ladder, every raw-data
   cell collapses: 8 of 66 edges at p = 50 (DiNA data), and 0 of 51 for
   `simulate_ssjgl_data` at p = 50, where the PIP AUC is 1.0. p enters only
   through logit(pi) ~ log(density) ~ log(2/p), which moves A* from 0.70
   (p = 50) to 0.92 (p = 250) at r = 16. This makes the collapse more
   complete at larger p but does not cause it. The DiNA p = 200,
   lambda1/v0 = 50 run over-selected for the same reason in the other
   direction: A* is small there.

5. **More data does not fix it.** The E-step threshold does not depend on n.
   At n = 2000 the estimates are no longer shrunk (median A-hat 0.37 ≈ the
   true 0.36), but with the DiNA ladder still only 44 of 383 edges get
   PIP > 0.5 and PIP2 is identically 0. This is consistent with DiNA seeing
   the collapse up to n = 5000.

6. **Scale and b are second-order.** b = 1 vs b = p changes nothing beyond
   the third digit: b pseudo-counts are negligible against N = 31,125 pairs.
   Standardising multiplies DiNA's theta by about 1.25, which moves the DiNA
   ladder from 6 to 68 PIP > 0.5 at p = 250 (and from 0 to 10 for `sim`). That
   is still under-selection, and the effect is not monotone in the sim data
   (raw sd 0.86). The raw data's scale is not the mechanism: DiNA's variances
   are close to 1.

7. **The PIPs keep their ranking.** Even when collapsed (PIPs ~1e-6), the
   PIP1 AUC is 0.94 to 1.0, because the PIP is a monotone function of A-hat
   = sum_g |theta-hat|. Ranking by PIP equals ranking by |theta-hat|.

## Proposed fix and guidance (not implemented in package code)

1. **DiNA: use the package default ladder** (drop `v0s`, i.e.
   `make_v0_ladder(lambda1)`, lambda1/v0 = 10, 31.6, 100) and preferably
   `standardize = TRUE`. In the DiNA setting this gives 264 of 383 edges with
   PIP > 0.5 at p = 250 (n = 250) and 342 of 383 at n = 2000, with an
   expected 3 and 0.03 false positives (sum of PIPs over non-edges). This
   agrees with `data-raw/v0-ladder-study.R`, which found that the DiNA ladder
   under-selects.
2. **Documentation rule for `v0s`.** For G groups, an edge needs roughly
   sum_g |theta_g| > A* = (G log r - logit pi)/(r - 1) to get PIP > 1/2, with
   r = lambda1/v0 at the last step and pi ~ the edge density (~2/p for a
   sparse graph). For G = 2 and p = 250 this gives a per-group |theta|
   threshold of about 0.35 at r = 16, 0.19 at r = 31.6, 0.07 at r = 100 and
   0.03 at r = 316. Choose the last step so that this threshold is below the
   smallest partial-correlation-scale effect of interest, on standardised
   data. Use `n` only for the M-step guide that is already in `?ssjgl`; the
   E-step threshold does not depend on n.
3. **Possible package changes** (separate PRs):
   - include pi in the EM convergence check (e.g. |Delta logit pi| < tol),
     so a step does not stop mid-collapse;
   - keep pi away from exactly 0 (floor at 1/N, or recommend a > 1), so that
     pi = 0 is not absorbing and `problist2` cannot be identically 0;
   - warn when the last step has pi_delta < 1/N or no PIP > 0.5;
   - optionally carry pi across ladder steps along with theta.
4. **DiNA Bayesian FDR.** Do not apply Bayesian-FDR thresholds to SSJGL PIPs.
   Under the default ladder they are almost all 0 or 1 (99% of pairs below
   1e-6 at p = 250), so a PIP-based FDR estimate is about 0 at any threshold.
   Treating them as a score for permutation-based inference, as DiNA already
   does, is appropriate.

## What the software paper can and cannot claim about PIPs

It can claim:

- `problist1` / `problist2` are the E-step conditional inclusion
  probabilities P(delta = 1 | theta-hat, pi-hat) of an EM / MAP procedure, as
  in Li et al. (2019) and EMVS (Rockova & George, 2014).
- PIP > 0.5 at the last step of a suitable ladder is a median-probability-
  model-style selection rule with good accuracy in our simulations (default
  ladder: about 65% to 100% of true edges selected, few false positives).
- PIPs rank edges well (AUC 0.84 to 1.0 here).

It cannot claim:

- that they are marginal posterior probabilities or calibrated
  probabilities. They condition on a point estimate, are a logistic function
  of |theta-hat| with slope lambda1/v0, and are pushed to 0 or 1;
- that they quantify uncertainty or support Bayesian FDR control;
- that their values are comparable across v0 ladders or lambda1. The same
  data give 6 or 264 selected edges depending only on the last lambda1/v0;
- anything about `problist2` (differential edges) beyond ranking. It is the
  most fragile output: it is identically 0 under the DiNA ladder and 0 or 1
  under the default ladder, with AUC 0.55 to 0.98.
